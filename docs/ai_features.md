# AI Features

ModelBrief can optionally include AI-generated explanations and recommendations alongside its analytical results.

The AI feature is not required to use ModelBrief. Reports, metrics, analysis, visualisations, and exports continue to work when AI is disabled.

## How it works

ModelBrief first performs the normal model evaluation. AI assistance then summarises the relevant results and may suggest areas worth investigating.

The AI features are provided as an optional layer:

1. ModelBrief evaluates the trained model.
2. Metrics and analysis results are collected.
3. The optional AI module creates explanations or recommendations.
4. Results are added to the generated report.
5. Users review the AI output before acting on it.


## Enable AI

Install the optional AI dependency:

```bash
pip install "modelbrief[ai]"
```

Then pass `ai=True` when creating the report:

```python
from modelbrief import ModelBrief

report = ModelBrief(
    model=model,
    X_test=X_test,
    y_test=y_test,
    ai=True,
)

report.show()
```

The default is `ai=False`. When AI is enabled, ModelBrief adds an **AI EXPLANATION** section and AI recommendations to the report.

## Configure Groq

Create a Groq API key in your Groq account, then provide it through the `GROQ_API_KEY` environment variable. Never place the key directly in source code or commit it to the repository.

macOS or Linux:

```bash
export GROQ_API_KEY="your-api-key"
export MODELBRIEF_GROQ_MODEL="openai/gpt-oss-20b"  # optional
```

Windows PowerShell:

```powershell
$env:GROQ_API_KEY="your-api-key"
$env:MODELBRIEF_GROQ_MODEL="openai/gpt-oss-20b"  # optional
```

Windows Command Prompt:

```cmd
set GROQ_API_KEY=your-api-key
set MODELBRIEF_GROQ_MODEL=openai/gpt-oss-20b
```

`MODELBRIEF_GROQ_MODEL` is optional. If it is not set, ModelBrief uses `openai/gpt-oss-20b`.

For the complete setup instructions, see [Groq AI, optional](../README.md#groq-ai-optional).

## What the AI adds

After the normal report analysis is complete, ModelBrief sends a shortened report-result summary to Groq.

The explanation request asks for:

- Three to five concise findings
- Important patterns or limitations in the evaluation results
- Findings based only on the supplied report data

The recommendation request asks for:

- Three to five practical recommendations
- Suggestions supported by the supplied results
- No claims that the model was retrained or changed

AI output is supplementary. The console, HTML, and PDF report content is still generated by the library's normal metrics and visualisation components.

## Missing dependencies or configuration

With `ai=True`:

- If `GROQ_API_KEY` is missing, report creation raises a `GROQ_API_KEY is required when ai=True` error.
- If the Groq Python package is missing, ModelBrief asks you to install support with `pip install "modelbrief[ai]"`.

Keep AI disabled if you do not need it or cannot configure the external service:

```python
report = ModelBrief(model, X_test=X_test, y_test=y_test, ai=False)
```

This option is the default and does not load the Groq integration.

## Security and privacy

When AI is enabled, ModelBrief sends report-result data to Groq. The payload is a JSON representation of the report, limited to the first 7,000 characters. It may therefore contain evaluation metrics and supplied or derived report metadata.

Before enabling AI:

- Review the report data that may be transmitted.
- Do not put API keys in source files or commit them to version control.
- Keep sensitive datasets, private records, and confidential model details out of reports sent to an external provider.
- Use environment variables or your platform's secure secret storage for credentials.

Core reports can be used without AI when data must remain entirely within the local environment.

## Limitations

AI output can be incomplete or inaccurate. It should not replace validation by a data scientist or domain expert, and it must not be treated as evidence that the model is production-ready.

The model guidance is generated from the supplied report summary rather than from an independent audit. It does not retrain or change the model, and a recommendation does not prove that making the suggested change will improve it.

Review findings and recommendations alongside the underlying metrics, dataset assumptions, and report warnings. If an external provider is unavailable or the API configuration is invalid, normal report generation is affected only when `ai=True`; keep AI disabled for a local-only report.

If the AI dependency or API key is missing, the core report should remain available.
Optional AI failures should be treated as optional warnings rather than a reason to discard all normal report results.
